# Application review and launch boundaries

## Public presentation and discovery

Public pages keep the existing restrained navy/white/orange brand, proposed service copy and visibly labeled concept truck image. Responsive Next Image sources now match the actual content widths; the hero is preloaded, secondary photography stays lazy and fixed image dimensions/aspect ratios prevent layout movement. The original image remains unchanged and has ordinary public-asset read permissions. A local SVG icon and a prerendered 1200×630 PNG sharing card use the central company name, with no unverified business numbers, certifications, prices or testimonials.

`PUBLIC_SITE_URL` is an optional approved **public HTTPS origin**. Set it before the production build. When absent, a valid public HTTPS `APP_URL` is the fallback. Credentials, paths, queries, fragments, HTTP and loopback URLs are never accepted as an explicit SEO origin. No request Host is trusted to choose canonicals. Until a real public origin is configured, canonicals/share-image URLs remain unset, the sitemap is empty and crawling is discouraged; no company domain is invented. Next normalizes the equivalent root URLs with/without a trailing slash.

Every public page has its own title, description, canonical and Open Graph/Twitter metadata when configured. `/sitemap.xml` includes only Home, Services, How It Works, About and Contact, with no fabricated modification dates. `/robots.txt` excludes dashboard, API and account routes. Private pages have distinct generic titles, noindex/nofollow/noarchive/nosnippet, no inherited public canonical/social card and the existing private no-store/no-referrer/X-Robots-Tag headers. These discovery rules **do not authorize access**: signed sessions and live server-side scopes remain mandatory for every protected read/write/export.

## Accessibility and feedback

All main landmarks can receive keyboard skip-link focus. Public and workspace disclosure menus support Escape with focus return. Fixed-space pending-link feedback indicates slow navigation without shifting labels. Public route loading and public/private/root error boundaries give clear retry destinations; errors never render a raw stack, database message or credential. Private record-not-found content avoids nested main landmarks and does not reveal whether another team's ID exists.

Private headings now use a consistent smaller scale; mobile form controls use 16px text, and footer links have larger targets. Focus outlines cover inputs, textareas, selects, summaries, scroll regions and feedback. Reduced-motion media preferences disable smooth scrolling, transitions and animations. The Admin Users screen now has search/20-row pages, while account and membership selectors include all permitted users beyond the former 50-row cap. The `/api/users` read is independently Admin-only. Tables keep contained horizontal scrolling and their pagination; no page-wide overflow is intended.

Authentication and management forms prevent duplicate clicks, report busy state, preserve values on recoverable failures and focus their feedback. Management validation identifies the affected fields and readable labels. Private controls are disabled before hydration. Existing consultation retry UUIDs, imported-batch idempotency, versioned edits and approval rules remain unchanged. No saved/approved message is shown before a successful server response. A common calendar validator now rejects year zero before it can fail in PostgreSQL, while preserving valid century/leap/DST behavior.

Dashboard navigation uses inline pending feedback instead of a broad streaming fallback around scoped record reads. This keeps authentication and missing-record checks ahead of response streaming, preserving real 307/404 responses. An indexing rule or hidden button never replaces the actual data boundary.

## Reproducible checks

Run `npm run lint`, `npm run typecheck`, `npm test`, `npm run db:validate` and `npm run build`. Generate Prisma first on a fresh checkout. The unit suites cover role scopes, inquiry save/email boundaries, strict input, exact approved totals/currencies, ranking ties, campaign-local dates, import bounds/formulas and SEO/private indexing invariants.

`npm run test:smoke` requires a local HTTPS app bound to an **empty dedicated `_test` PostgreSQL database**, `TEST_DATABASE_URL`, matching `SMOKE_BASE_URL`, random `AUTH_SECRET` and trusted certificate via `NODE_EXTRA_CA_CERTS`. It exercises actual invitation/login/sessions, public save/triage/assignment, cross-team/role/export boundaries, submission/approval/corrections/ties/date filters and transactional CSV/XLSX imports/retries. The joined application journey runs one inquiry through assignment, manual daily submission, review approval and a verified exact leaderboard update. Manual activity counts are not automatically inferred from a lead status and remain the documented activity ratio.

`npm run test:browser` uses Playwright Test and axe-core. It requires the same migrated **empty `_test` database and loopback HTTPS app**, with test mail delivery disabled. Supply an isolated `PUBLIC_SITE_URL` for metadata checks; it is used only by that disposable review build/runtime. The app and test runner must use the same test database. `PLAYWRIGHT_CHROMIUM_EXECUTABLE` can select an installed Chromium; the cloud default is `/usr/bin/chromium`. On another machine, install the maintained Playwright Chromium browser and supply its path. Set `REVIEW_OUTPUT_DIR` outside the repository for screenshots/results.

The browser test creates cryptographically random invitation-only review accounts, checks public/account/Admin/Manager/Dispatcher/outside-team screens at 1440, 1024, 768, 390 and 320 pixels, validates keyboard/reduced-motion/image/SEO states and performs the joined journey through real controls. It imports 60 producers as Draft, then submits/approves through the actual guarded endpoints and checks large-table pagination. Traces/videos/automatic failure screenshots are disabled to avoid capturing credentials. Temporary invitations and all isolated business/account/session fixtures are cleaned afterward. Do not run either journey on production or existing business data.

Next build workers must not inherit a `node --env-file` executable flag in `NODE_OPTIONS`. For a private test environment file, load it with the installed dotenv library in a small parent launcher and spawn `next build`/the Playwright CLI with the resulting environment and ordinary Node arguments. Keep all secrets outside the checkout. After testing with an isolated public test origin, rebuild with the actual deployment configuration; the review origin must not become a production canonical.

## Remaining launch work

Production hosting, the actual public domain, secure PostgreSQL/auth runtime values, first real Admin bootstrap and optional verified mail-provider delivery require operator configuration. Current tests establish the disposable local workflow, not production connectivity, physical-device/Safari behavior, sustained production concurrency, backup restoration or external monitoring. No automatic production seed or default credentials exist. Company facts/services, legal/privacy content and any actual operational claims still need operator approval before public launch. Completed test counts and observed fixes are recorded in `VERIFICATION.md`.
